# ระบบคอร์สและการปลดล็อก

**อัปเดต beta:** ติดตั้งฐานจริงด้วย `classroom-beta-isolated.sql` แล้ว โดยไม่แก้ profiles หรือ trigger เดิม ดู [คู่มือปัจจุบัน](BETA-ADMIN.md) เอกสารด้านล่างเป็นแผน Next.js draft ก่อนปรับใช้ GitHub Pages

โค้ดฐานข้อมูลชุดนี้ยังไม่ได้ติดตั้งใน Supabase จริง ไม่มีการเปลี่ยนข้อมูลหรือสิทธิ์ของนักเรียนเดิมระหว่างสร้างโครงร่าง

## ติดตั้งเมื่อพร้อมเปิดระบบจริง

1. ใช้ฐานข้อมูลที่ติดตั้ง migration เดิมใน `supabase/migrations/` แล้ว
2. ตรวจและรัน `supabase/setup/classroom.sql` ผ่าน SQL Editor ของโปรเจกต์ที่เลือก ไฟล์นี้เพิ่มเฉพาะตาราง `classroom_*`, ฟังก์ชันและ policy ที่ใช้กับระบบคอร์ส และคอลัมน์ username ใน profiles
3. เก็บ schema `classroom_private` ไว้นอก Data API exposed schemas
4. เปิด Supabase Security Advisors หลังติดตั้ง และตรวจ RLS ด้วยบัญชีนักเรียนสองคนและแอดมินในฐานข้อมูลทดสอบก่อนนำขึ้นใช้งาน
5. เมื่อมี Supabase CLI ให้สร้าง migration ด้วย `supabase migration new classroom` แล้วนำ SQL ชุดนี้ใส่ไฟล์ที่ CLI สร้าง เพื่อเก็บประวัติการติดตั้ง โฟลเดอร์งานปัจจุบันไม่มี CLI จึงไม่สร้างชื่อ migration ขึ้นเอง

สคริปต์ตั้งค่าแทนที่ trigger function `public.prevent_role_change` ด้วย `SECURITY INVOKER` ที่อนุญาตให้เฉพาะ database roles `postgres`, `service_role` หรือ `supabase_admin` เปลี่ยน role ของบัญชีได้ ผู้ดูแลจึงตั้งแอดมินคนแรกผ่าน SQL Editor ได้หลังติดตั้ง นักเรียนและครูที่ใช้ session เว็บยังเปลี่ยน role ตัวเองไม่ได้ แม้จะแก้ request หรือเรียก Data API เอง

ก่อนเริ่มใช้จริงต้องมี `NEXT_PUBLIC_SUPABASE_URL` และ `NEXT_PUBLIC_SUPABASE_ANON_KEY` ตามระบบเดิม ส่วน service role ใช้เฉพาะเซิร์ฟเวอร์สำหรับออกบัญชีนักเรียน ห้ามใช้ตัวแปรชื่อขึ้นต้น `NEXT_PUBLIC_` เก็บ service role

## กฎสิทธิ์เรียน

- ทุกคนเห็นชื่อคอร์สและหัวข้อเลเวลได้ แต่ลิงก์ Drive และรายละเอียดรายการเรียนอ่านได้เฉพาะผู้มีบัญชีและได้รับสิทธิ์คอร์สนั้น ถึงเลเวลที่แอดมินปลดไว้
- ไม่รับ Supabase anonymous session เป็นบัญชีเรียน ทั้งในหน้าเว็บ/server action และ RLS ฐานข้อมูล
- สิทธิ์เรียนเก็บใน `classroom_enrollments` นักเรียนแก้ไขตารางนี้ผ่าน Data API ไม่ได้ แม้จะเรียก API เองนอกหน้าเว็บ
- เปิดคอร์สใหม่ให้นักเรียนเริ่มที่ Level 1 เท่านั้น การเรียกเปิดคอร์สซ้ำไม่รีเซ็ตหรือเพิ่มเลเวล
- นักเรียนติ๊กรายการวิดีโอ/HW ของตัวเองได้เท่านั้น เป็นการแจ้งว่าเรียน/ทำงานแล้ว ไม่ได้ตรวจความถูกต้องของ HW หรือพิสูจน์ว่าเล่นวิดีโอครบ
- ติ๊กรายการครบยังไม่เปิดเลเวลถัดไป ต้องทัก LINE ตามขั้นตอนของติวเตอร์ และแอดมินกดปลดล็อกเอง
- คำสั่งแอดมินเปิดได้ครั้งละหนึ่งเลเวล ต้องมีรายการเรียนในเลเวลปัจจุบันและนักเรียนติ๊กครบ ห้ามข้ามเลเวล รอข้อมูลในกรณียังไม่มีเนื้อหา
- คำสั่งปลดล็อกใช้ transaction, row lock และ expected level ป้องกันคำสั่งซ้ำจากหน้าที่แสดงข้อมูลเก่า
- ถอนสิทธิ์คอร์สแล้วนักเรียนอ่านรายการเรียน/อัปเดต progress ในคอร์สนั้นไม่ได้อีก ประวัติ progress เก็บไว้ ถ้าเปิดสิทธิ์ใหม่จะกลับไปเริ่มที่ Level 1 แต่ประวัติรายการเดิมยังอยู่
- ตรวจแอดมินจาก `profiles.role` ที่ระบบเดิมป้องกันการเปลี่ยนโดยนักเรียน ไม่ใช้ `user_metadata` ตัดสินสิทธิ์

บัญชีที่ออกให้ใช้ email ภายในรูปแบบ `username@classroom.invalid` เพื่อให้ Supabase Auth รองรับ username/password หน้าเว็บแสดงเฉพาะ username และรับข้อมูลเข้าระบบจากติวเตอร์ ไม่ใช่ที่อยู่อีเมลสำหรับรับข้อความ username ถูกตั้งจาก email ใน auth.users และป้องกันนักเรียนเปลี่ยนเอง

## เพิ่มเนื้อหาจากแชท

1. อัปเดตหัวข้อและชั่วโมงใน `classroom_levels` และ metadata หลักสูตรที่หน้าเว็บใช้
2. เพิ่ม `classroom_items` พร้อม `course_id`, `level_number`, `kind` (`video`/`homework`), ชื่อรายการ, เวลาที่ใช้/เวลาแนะนำ, ลำดับ และ `drive_file_id` ของคลิปหรือ HW
3. เก็บเฉพาะ file ID ของ Drive ไม่เก็บ URL อื่นโดยพลการ เส้นทาง media ฝั่งเซิร์ฟเวอร์ตรวจสิทธิ์ก่อนส่งต่อไป preview ของ Drive
4. คอร์ส Camp 1, Camp 2 และ TPhO เริ่มต้นมี `level_count = null` จึงยังเปิดลงทะเบียนไม่ได้ ต้องเพิ่มระดับและกำหนดจำนวนเลเวลก่อน

ฐานข้อมูลไม่ได้ใส่คลิปหรือ HW สาธิตของหน้า preview และไม่ใส่ชั่วโมงสมมุติ หัวข้อ Pre-POSN 31 เลเวลอ้างจาก draft และยังต้องยืนยันเนื้อหาจริง

## การตรวจสอบที่ยังต้องทำกับฐานข้อมูล

เครื่องนี้ไม่มี PostgreSQL/Supabase CLI จึงยังไม่ได้รัน SQL หรือ Security Advisors ตรวจจริง สคริปต์ยังเป็นงานเตรียมติดตั้ง ต้องทดสอบหลังติดตั้งในฐานทดสอบอย่างน้อยดังนี้:

1. บัญชีที่ไม่เข้าสู่ระบบและบัญชีที่ไม่ลงคอร์สอ่าน `classroom_items` ไม่ได้
2. นักเรียน A ที่ปลดถึง Level 1 เห็นเฉพาะรายการถึง Level 1 และอ่าน/แก้ progress ของ B ไม่ได้
3. นักเรียนเรียก RPC ทั้งสามรายการ (`classroom_enroll_student`, `classroom_advance_student`, `classroom_revoke_student`) ต้องถูกปฏิเสธ และแก้ `classroom_enrollments` โดยตรงไม่ได้
4. แอดมินเปิด Level 2 ไม่ได้เมื่อ Level 1 ว่าง/ยังติ๊กไม่ครบ แต่เปิดได้เมื่อครบแล้ว และคำสั่ง expected level เดิมต้องใช้ซ้ำไม่ได้
5. ถอนสิทธิ์แล้วอ่าน Drive ID หรือบันทึก progress ไม่ได้ และนักเรียนเปลี่ยน username/role ตัวเองไม่ได้
6. Supabase anonymous user ไม่เห็นข้อมูลลงคอร์ส เนื้อหา หรือ progress แม้จะมี authenticated database role

Unit tests ใน `src/app/courses/actions.test.ts` ตรวจขอบเขตการเรียก server actions และการไม่เปิดเลเวลอัตโนมัติ แต่ไม่ใช้แทนการทดสอบ RLS ใน PostgreSQL
