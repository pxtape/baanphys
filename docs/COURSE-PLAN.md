# โครงระบบคอร์ส บ้านฟิสิกส์

โครงร่างตาม draft วันที่ 21 ตุลาคม 2026 เน้นโครงสร้างและสิทธิ์ก่อนตกแต่ง ผู้ดูแลส่งเนื้อหาผ่านแชทให้ Codex ใส่ข้อมูลต่อได้ ไม่จำเป็นต้องแก้ไฟล์เอง

## หน้าหลักและเส้นทาง

- `/` ทางเข้าเรียนและลิงก์ตัวอย่าง
- `/login` Username + รหัสผ่านที่ผู้ดูแลสร้างให้ ไม่มีหน้าสมัครสมาชิกคอร์สเอง
- `/courses` คอร์สของนักเรียนและ pathway; ทุกคนเห็นชื่อ Pre-POSN, Camp 1, Camp 2, TPhO แต่เปิดได้เฉพาะคอร์สที่ได้รับสิทธิ์
- Pre-POSN แสดง Level 1–31 พร้อมชื่อหัวข้อและเวลา เมื่อมีข้อมูลจริง
- คลิกเลเวลที่เปิดแล้วเพื่อดู checklist วิดีโอ/HW และเวลาแนะนำ
- `/admin/students` ผู้ดูแลค้นหานักเรียน เพิ่มบัญชี เปิด/ปิดสิทธิ์คอร์ส และกดเปิดเลเวลถัดไป
- `/preview/classroom` และ `/preview/admin` ตัวอย่างแบบโต้ตอบ ข้อมูลจำลองในเบราว์เซอร์ แยกจากสิทธิ์จริง

## กติกา

1. ผู้ดูแลเป็นผู้สร้าง Username และรหัสผ่านเริ่มต้น ไม่มีการแจกบัญชีจริงในโค้ด
2. เมื่อเปิดสิทธิ์คอร์ส นักเรียนเริ่มที่ Level 1
3. เลเวลที่ได้รับสิทธิ์แล้วกลับไปเรียนซ้ำได้
4. นักเรียนติ๊กรายการวิดีโอและ HW ว่าทำแล้ว ระบบนี้ไม่ได้ตรวจว่าดูคลิปจริงครบทุกวินาที
5. รายการครบอย่างเดียวไม่เปิดเลเวลถัดไป นักเรียนต้องคุยกับติวเตอร์ทาง LINE ตามปกติ
6. แอดมินกดปลดล็อกได้ทีละหนึ่งเลเวล หลังระบบตรวจว่ารายการปัจจุบันครบ ไม่มีการเชื่อม LINE หรือแจ้งติวเตอร์อัตโนมัติ
7. เลเวลที่ยังไม่มีรายการเรียนจริงจะไม่ถือว่าเรียนจบ ป้องกันการเลื่อนผ่านช่องว่าง
8. สิทธิ์คอร์ส เลเวล และเนื้อหาตรวจฝั่งฐานข้อมูลด้วย ไม่อาศัยแค่ปุ่มล็อก

## ข้อมูลที่รอเจ้าของคอร์สส่งในแชท

ส่งครั้งละเลเวลหรือหลายเลเวลก็ได้ เช่น

```text
คอร์ส: Pre-POSN
Level: 1
ชื่อบท: ...
วิดีโอ 1: ชื่อ ... / ลิงก์ Drive ... / ยาว ... นาที
วิดีโอ 2: ...
HW: ชื่อ ... / ลิงก์ Drive ... / เวลาทำประมาณ ... นาที
เวลาแนะนำทั้งหมด: ...
คำแนะนำเพิ่มเติม: ...
```

ชื่อหัวข้อในตัวอย่างถอดจากภาพ draft เท่านั้น ไม่ใช่หลักสูตรที่ยืนยันแล้ว ในภาพ Level 16 ระบุทั้ง SHM และ Fluid คนละหน้า จึงรอยืนยัน ส่วน Level 21 ไม่ปรากฏรายละเอียด ไม่มีการเดาข้อมูลหรือชั่วโมงจริงให้

ตัวอย่าง Pre-POSN มีวิดีโอ 1 ชม. + HW 3 ชม. ตามภาพไว้ทดลอง checklist ข้อมูลสาธิตนี้ไม่ถูก seed ลงฐานข้อมูลจริง Camp 1 / Camp 2 / TPhO รอจำนวนเลเวลและเนื้อหา

## Google Drive และการลดการส่งต่อ

เส้นทางเนื้อหาตรวจ login และสิทธิ์ก่อนคืน iframe พร้อมลายน้ำชื่อ/Username/เวลา ไม่ cache เนื้อหาส่วนตัว และไม่วางลิงก์ Drive จริงใน catalog สาธารณะ

Google Drive ต้องตั้ง Restricted และแชร์ให้บัญชี Google นักเรียนที่ได้รับอนุญาต หรือกลุ่มที่ดูแลเอง การล็อกอินเว็บไม่ได้ให้สิทธิ์ Google Drive อัตโนมัติ นักเรียนอาจต้องล็อกอิน Google อีกบัญชีใน browser ด้วย เปิดตัวเลือกห้ามดาวน์โหลด/พิมพ์/คัดลอกของผู้ดูใน Drive เท่าที่ประเภทไฟล์และบัญชีรองรับ

ลายน้ำและการล็อกช่วยเพิ่มความยากในการส่งต่อ แต่ผู้ที่ได้รับสิทธิ์ยังตรวจพบ URL หรือบันทึกหน้าจอได้ ลายน้ำ iframe ไม่ติดไปกับไฟล์ต้นฉบับ ตัวเว็บขยายเต็มจอทั้งกรอบรวมลายน้ำและไม่ให้ iframe ของ Drive แยกเต็มจอ หากภายหลังต้องการป้องกันมากขึ้นควรใช้บริการวิดีโอที่รองรับ signed playback หรือ DRM

## GitHub และการเปิดใช้จริง

GitHub เก็บ source code เว็บนี้มี server actions และ Supabase auth จึงไม่สามารถใช้ GitHub Pages แบบไฟล์ static เพียงอย่างเดียวได้ ต้อง deploy บนโฮสต์ที่รัน Next.js ได้ แล้วตั้ง environment variables และติดตั้ง SQL schema ก่อนสร้างบัญชีจริง

ห้ามนำ `.env.local`, service-role key, รหัสผ่านนักเรียน, ไฟล์การบ้านจริง หรือคลิปขึ้น repository เนื้อหา Drive จริงเก็บในฐานข้อมูลที่ตรวจสิทธิ์ โครงสร้างข้อมูลและคำสั่ง setup อยู่ในคู่มือ backend/auth แยกกัน

## ลองตัวอย่าง

1. เปิดหน้าตัวอย่างนักเรียน กดเข้า Pre-POSN แล้วเลือก Level 9
2. ติ๊กวิดีโอและ HW จะเห็นว่า Level 10 ยังคงล็อก
3. เปิดหลังบ้านตัวอย่าง เลือก `student.demo` แล้วกดปลดล็อก Level 10
4. กลับหน้าตัวอย่างนักเรียน สิทธิ์ใหม่จะปรากฏ เมื่อ focus หน้าเดิมหรือโหลดใหม่

ข้อมูลตัวอย่างอยู่ใน localStorage ของ browser profile เดียวกัน ไม่ส่งไปฐานข้อมูลจริง
